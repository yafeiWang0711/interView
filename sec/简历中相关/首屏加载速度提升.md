### 首屏加载速度提升
    1. 静态资源的压缩和精简合并
        html: 去除多余的空格和注释 使用构建工具
        css: 压缩合并 移除未使用的样式
        js: 通过 Terser 压缩（webpack 5 内置），开启 tree-shaking 移除死代码：
            开启 tree-shaking 后，webpack 会分析代码中的导出和导入，只保留被使用的代码，从而减少打包体积。、
        图片：压缩合并 使用 webp 格式，懒加载，选择合适的格式。
            图片格式：使用 WebP 格式，因为 WebP 格式支持有损压缩和无损压缩，压缩率高，加载速度快。
            图片压缩：使用工具如 ImageOptim 或 TinyPNG 压缩图片，减少图片体积。
            图片懒加载：使用 React 或 Vue 提供的图片懒加载组件，只加载当前视口内的图片，其他图片延迟加载。
        字体：压缩合并 移除未使用的字符集

        删除冗余的代码：
            移除未使用的代码：使用工具如 Webpack Bundle Analyzer 分析打包体积，移除未使用的代码。
            移除重复的代码：使用工具如 UglifyJS 或 Terser 压缩代码时，开启去重选项。
    
    2. 代码精简：
        只加载首屏必需的代码，其他代码按需加载
        路由级代码分割（React/Vue 通用）
        通过动态 import 拆分代码，首屏只加载当前路由的代码，其他路由延迟加载
        首屏不需要的组件（如弹窗、图表、异步表单）通过动态导入延迟加载：
        动态导入语法：
            React：React.lazy 组件
            Vue：动态 import 语法
    
    3. 关键资源优先加载
        css：
            1. 将首屏渲染必需的 CSS（如头部导航、Banner 样式）内联到 HTML 的 <style> 标签中，避免额外的 CSS 文件请求（减少 1 次 HTTP 请求，且避免 CSS 阻塞首屏渲染）。
            2. 非首屏 CSS（如页脚、详情页样式）用 <link rel="preload" as="style" href="non-critical.css" onload="this.onload=null;this.rel='stylesheet'"> 异步加载。
        js：
            1. 非首屏 JS（如统计脚本、第三方广告）用 defer 或 async 延迟加载：
                defer：JS 加载不阻塞 DOM 解析，按顺序执行（适合依赖顺序的脚本，如 jQuery 后加载插件）。
                async：JS 加载不阻塞 DOM 解析，加载完成后立即执行（适合无依赖的独立脚本，如统计代码）。
            2. 首屏关键 JS（如首屏交互逻辑）：精简代码后内联到 HTML 中，避免外部请求。


    4.  预加载与预连接（提前建立连接 / 加载资源）
            预加载（Preload）：提前加载首屏即将用到的关键资源（如首屏图片、关键 JS/CSS），语法：
            html
            预览
            <link rel="preload" as="image" href="hero.webp" imagesrcset="hero-480.webp 480w, hero-1080.webp 1080w" imagesizes="100vw">
            <link rel="preload" as="script" href="critical.js">
            <link rel="preload" as="style" href="critical.css"> 
            ⚠️ 注意：仅预加载首屏必需资源，避免滥用导致资源浪费。
            预连接（Preconnect）：提前与第三方域名（如 CDN、接口服务器）建立 TCP 连接 + SSL 握手，减少后续请求的延迟，语法：
            html
            预览
            <link rel="preconnect" href="https://cdn.example.com"> <!-- 预连接 CDN 域名 -->
            <link rel="preconnect" href="https://api.example.com"> <!-- 预连接接口域名 -->

    5. 减少http请求
        1. 资源合并：非首屏的 JS/CSS 可合并为 1-2 个文件（避免过多小文件导致的 “请求排队”），但需平衡 “合并体积” 与 “缓存命中率”（若某小文件频繁更新，合并后会导致整个大文件缓存失效）。
        2. 雪碧图（Sprite）：将多个小图标合并为 1 张图片，减少图标请求数（适合不适合用 SVG 的场景），工具：SpriteSmith、在线雪碧图生成器。
        3. 内联资源：将极小的资源（如小图标 SVG、1KB 内的 JS/CSS）直接内联到 HTML 中，避免额外请求。

    6. 缓存策略优化
        1.浏览器缓存（强缓存 + 协商缓存）
            强缓存（优先使用，无 HTTP 请求）：
            适用于长期不变的静态资源，配置响应头：
            配置响应头 Cache-Control: max-age=31536000（单位：秒，1 年）或 Expires: Thu, 31 Dec 2025 23:59:59 GMT，适用于长期不变的静态资源（如图片、字体、第三方库）。
            注意：资源更新时需通过 “文件名哈希”（如 app.[hash].js）触发缓存失效（构建工具可自动生成哈希）。
            
            协商缓存（需发 HTTP 请求，但无响应体）：
            适用于可能更新的资源（如首页 HTML、非哈希命名的 JS/CSS），配置响应头：
            ETag: "abc123"（资源哈希值，服务器对比哈希判断是否更新）。
            Last-Modified: Wed, 20 Sep 2024 10:00:00 GMT（资源最后修改时间）。
        2. 使用 CDN 缓存：
            配置 CDN 缓存策略，将静态资源缓存到 CDN 节点，减少请求到源服务器的延迟。
            配置 CDN 缓存时间：根据资源更新频率和访问频率，配置 CDN 缓存时间（如 1 天、1 周），避免资源更新后缓存未失效。
            配置 CDN 缓存策略：根据资源类型（如图片、字体、JS/CSS），配置不同的缓存策略（如强制缓存、协商缓存）。
    
    7. 渲染效率优化
        1.减少DOM操作：
            减少 DOM 操作次数：避免频繁操作 DOM，如批量操作、缓存 DOM 元素。
            减少 DOM 操作频率：避免在循环中操作 DOM，如使用事件委托、虚拟 DOM 技术。
        2. 减少重绘和回流：
            减少重绘和回流次数：避免频繁操作样式、位置、大小等会触发重绘和回流的属性。
            减少重绘和回流频率：避免在循环中操作样式、位置、大小等会触发重绘和回流的属性。

    8. 服务器端渲染（SSR）或静态站点生成（SSG）：
        1. 服务器端渲染（SSR）：
            服务器端渲染（SSR）：在服务器端生成完整的 HTML 页面，返回给客户端。
            优势：SEO 友好、首屏渲染快。
            劣势：服务器负载高、开发成本高。
        2. 静态站点生成（SSG）：
            静态站点生成（SSG）：在构建时生成静态 HTML 文件，部署到静态文件服务器。
            优势：简单、成本低、性能好。
            劣势：不支持动态内容、更新需要重新构建。

        gzip 压缩
        开启 HTTP/2 协议
        配置缓存策略
