### 深浅拷贝区别，实现深拷贝有什么思路

    1. 浅拷贝：只复制对象的引用，而不复制对象本身。
    2. 深拷贝：复制对象本身，而不是对象的引用。
    3. 实现深拷贝的思路：
        1. 递归拷贝：遍历对象的所有属性，对每个属性进行判断，如果是对象，就递归调用深拷贝函数，否则直接赋值。
        2. 利用 JSON 序列化：将对象转换为 JSON 字符串，再将 JSON 字符串转换为新的对象。
        3. 利用 Object.assign() 方法：该方法可以将一个对象的属性复制到另一个对象中。
        4. 利用 ES6 扩展运算符：该运算符可以将一个对象的属性展开到另一个对象中。

### 对 this 的理解

    this 指向的是函数执行时的上下文对象。在全局环境下，this 指向全局对象（window 或 global）。在函数内部，this 的值取决于函数的调用方式。
    1. 普通函数调用：this 指向全局对象（window 或 global）。
    2. 方法调用：this 指向调用该方法的对象。
    3. 构造函数调用：this 指向新创建的对象。
    4. 箭头函数调用：this 指向定义该箭头函数的上下文对象。

### 改变 this 指向的方法

    1. call() 方法：调用一个函数，同时指定 this 的值和参数。
     
        Function.prototype.MyCall = function(context, ...args) {
            context = context || window;
            context.fn = this;
            const result = context.fn(...args);
            delete context.fn;
            return result;
        }
  
       
    2. apply() 方法：调用一个函数，同时指定 this 的值和参数数组。
        Function.prototype.MyApply = function(context, args) {
            context = context || window;
            context.fn = this;
            const result = context.fn(...args);
            delete context.fn;
            return result;
        }
    3. bind() 方法：创建一个新的函数，同时指定 this 的值和参数。
        Function.prototype.MyBind = function(context, ...args) {
            context = context || window;
            context.fn = this;
            return function(...args2) {
                const result = context.fn(...args, ...args2);
                delete context.fn;
                return result;
            }
        }

    4. 使用 Object.prototype.toString.call() 方法：判断一个对象的类型。

### 对原型链的理解

    1. 每个对象都有一个原型对象，原型对象也有自己的原型对象，直到某个对象的原型对象为 null。
    2. 当访问一个对象的属性时，如果该对象本身没有这个属性，就会去它的原型对象里找，直到找到为止。
    3. 原型链的查找过程是从下往上的，即先查找当前对象的属性，再查找它的原型对象的属性，直到找到为止。

### 对事件循环的理解
    1. 事件循环是指浏览器或 Node.js 等环境中的一种机制，用于处理异步操作。
    2. 事件循环的基本原理是：将异步操作放到事件队列中，当同步操作执行完毕后，再从事件队列中取出异步操作进行执行。
    3. 事件循环的机制是基于回调函数的，当异步操作完成后，会调用对应的回调函数。
    4. 事件循环的机制是基于宏任务和微任务队列的，宏任务队列和微任务队列分别存储不同类型的异步操作。
    5. 宏任务队列：包括 setTimeout、setInterval、setImmediate、I/O 操作、UI 渲染等。
    6. 微任务队列：包括 Promise、async/await、MutationObserver 等。

### 为什么有宏任务和微任务队列的区分
    1. 宏任务队列：包括 setTimeout、setInterval、setImmediate、I/O 操作、UI 渲染等。
    2. 微任务队列：包括 Promise、async/await、MutationObserver 等。
    3. 微任务队列的优先级高于宏任务队列，即当事件循环执行到微任务队列时，会先执行完所有微任务，再执行宏任务。
    4. 微任务队列的执行时机是在当前宏任务执行完毕后，下一个宏任务执行前。

### 实现垂直居中布局的方法
    1. 使用 flex 布局：将父元素设置为 display: flex; align-items: center; justify-content: center;。
    2. 使用 grid 布局：将父元素设置为 display: grid; place-items: center;。
    3. 使用 position 定位：将子元素设置为 position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%);。
    4. 使用 margin 和 padding：将子元素的垂直方向上的外边距和内边距设置为 auto，使其居中。

### vue 组件通信方式
    1. props 和 events：通过父组件向子组件传递数据和事件。
    2. provide/inject：祖先组件向子孙组件提供数据。
    3. $emit/$on：兄弟组件之间通信，通过自定义事件进行通信。
    4. Vuex：全局状态管理，适用于大型应用中多个组件之间的通信。
    5. EventBus：事件总线，适用于非父子组件之间的通信。

### vue 响应式原理
    vue2 使用 Object.defineProperty() 方法来劫持对象的属性，当对象属性的值发生变化时，自动更新视图。
        1. 初始化时，遍历对象的所有属性，使用 Object.defineProperty() 方法将每个属性的 setter 和 getter 都设置为一个函数。
        2. 当属性的值发生变化时，会调用属性的 setter 函数，在 setter 函数中会触发视图的更新。
    vue3 使用 Proxy 来劫持对象的属性，当对象属性的值发生变化时，自动更新视图。
        1. 初始化时，使用 Proxy 来劫持对象的属性，当属性的值发生变化时，会调用对应的 handler 函数。
        2. 在 handler 函数中，会触发视图的更新。
        3. 可以直接监听数组的变化，不需要使用特殊的方法。

### vue3 响应式重构，为什么要做，有什么好处
    1. 性能优化：使用 Proxy 来劫持对象的属性，当属性的值发生变化时，会直接触发视图的更新，避免了使用 Object.defineProperty() 方法的性能问题。
    2. 代码简洁：使用 Proxy 来劫持对象的属性，代码简洁，不需要使用特殊的方法来监听数组的变化。
    3. 支持动态添加属性：使用 Proxy 来劫持对象的属性，支持动态添加属性，不需要使用 Object.defineProperty() 方法的方式来添加属性。

### v - for 里 key 的作用
    1. 唯一标识：key 可以唯一标识一个元素，用于在 diff 算法中判断元素是否发生了变化。
    2. 性能优化：key 可以帮助 Vue 跟踪每个元素的变化，避免重复渲染。
    3. 避免列表渲染错误：key 可以避免列表渲染错误，例如元素的顺序发生了变化，导致渲染错误。

### dom diff 的原理
    1. 虚拟 DOM：将真实的 DOM 转换为 JavaScript 对象，称为虚拟 DOM。
    2. diff 算法：比较新旧两个虚拟 DOM 的差异，找出需要更新的部分。
    3. patch 方法：根据 diff 算法的结果，更新真实 DOM。
    4. 双端比较：diff 算法使用双端比较的方式，从新旧两个虚拟 DOM 的两端开始比较，找到相同的节点，再比较子节点。
    5. 列表比较：diff 算法可以直接比较列表的变化，不需要使用特殊的方法。
    6. 组件比较：diff 算法可以直接比较组件的变化，不需要使用特殊的方法。
