### cookie，localStorage，sessionStorage 的区别和使用场景
    cookie：
        大小为5kb，可以设置过期时间，会随着请求发送到服务器
        使用场景：用户登录状态、购物车信息，token等，跨页面传递数据
    localStorage：
        大小为5mb，不会过期除非手动删除，不会随着请求发送到服务器
        使用场景：表单信息、主题设置，可以实现vueX的持久化存储，跨页面传递数据
    sessionStorage：
        大小为5mb，不会过期除非关闭页面，不会随着请求发送到服务器
        使用场景：临时存储表单信息、页面刷新数据不丢失，但是关闭页面数据会丢失，标签页之间不会共享

### 闭包的概念和使用场景
    闭包是指有权访问另一个函数作用域中变量的函数的引用，即使外部函数已经执行完毕。
    使用场景：封装私有变量、实现模块化编程等
    例如：
        function fn() {
            let a = 1;
            function fn1() {
                console.log(a);
            }
            return fn1;
        }
        let fn2 = fn();
        fn2(); // 1
    注意：闭包会导致内存泄漏，因为外部函数的作用域不会被释放，但是内部函数的作用域会被释放
    例如：
        function fn() {
            let a = 1;
            function fn1() {
                console.log(a);
            }
            return fn1;
        }
        let fn2 = fn();
        fn2(); // 1
        fn = null; // 手动释放外部函数的作用域
### js 的事件循环机制
    Event Loop
    js 是单线程的，但是为了实现异步操作，所以引入了事件循环机制
    js 的事件循环机制是基于任务队列的，分为宏任务和微任务
    宏任务：script、setTimeout、setInterval、setImmediate、I/O、UI rendering
    微任务：Promise、MutationObserver、process.nextTick
    事件循环的流程：
        1. 执行全局 script 同步任务
        2. 执行微任务队列中的任务
        3. 执行宏任务队列中的任务
        4. 重复 2、3 步骤
    注意：
        1. 微任务队列中的任务会在宏任务队列中的任务之前执行
        2. 微任务队列中的任务会在当前宏任务执行完毕后执行
        3. 微任务队列中的任务执行完毕后，会检查宏任务队列是否为空，如果为空，会等待下一个宏任务到来
    例如：
        console.log('1');
        setTimeout(() => {
            console.log('2');
        }, 0);
        Promise.resolve().then(() => {
            console.log('3');
        });
        console.log('4');
    输出结果：1 4 3 2
    console.log('1'); // 同步任务

    例如：  
        setTimeout(() => {
        console.log('2'); // 宏任务
        Promise.resolve().then(() => console.log('3')); // 微任务
        setTimeout(() => console.log('7'), 0); // 宏任务
        }, 0);

        Promise.resolve().then(() => {
        console.log('4'); // 微任务
        setTimeout(() => console.log('5'), 0); // 宏任务
        });

        console.log('6'); // 同步任务

        // 1，6，4，2，3，5，7

### watch 和 watchEffect 的区别
    watch：
        1. 监听数据的变化，当数据变化时执行回调函数
        2. 可以深度监听对象和数组
        3. 可以立即执行回调函数
        4. 可以停止监听
    watchEffect：
        1. 自动收集依赖的响应式属性并执行副作用函数
        2. 当依赖改变时自动重新运行副作用函数
        3. 不需要手动指定要观察的数据项
        4. 可以停止监听

### InterSection Obverser 的工作原理
    Intersection Observer API 是一个用于检测目标元素是否进入另一个元素（通常是视口）的可观察区域，并触发回调函数的接口。
    工作原理：
        1. 创建一个 IntersectionObserver 对象实例
        2. 定义一个回调函数，该函数会在目标元素与根元素的交叉状态改变时被调用
        3. 使用 observe 方法开始监听目标元素
        4. 当目标元素进入或离开根元素的可见区域时，会触发回调函数
### 讲讲 vue 的双向绑定原理
    vue 的双向绑定原理是基于数据劫持和发布订阅模式的。
    数据劫持：通过 Object.defineProperty 方法来劫持各个属性的 setter，getter，在数据发生改变时，发布消息给订阅者，触发相应的监听回调。
    发布订阅模式：vue 中使用 Dep 类来管理订阅者，当数据发生改变时，会调用 Dep 类的 notify 方法，通知所有订阅者，订阅者会调用自己的 update 方法来更新视图。
### v-model 的原理
    v-model 是一个语法糖，本质上是 v-bind:value 和 v-on:input 的组合。
    当用户输入时，会触发 input 事件，vue 会将用户的输入赋值给 value 属性，从而实现双向绑定。
    例如：
        <input v-model="message" />
        // 等价于
        <input :value="message" @input="message = $event.target.value" />

### eventBus 的实现原理
    eventBus 是一个事件中心，它的实现原理是基于发布订阅模式的。
    1. 创建一个事件中心对象
    2. 定义一个事件中心对象的 on 方法，用于订阅事件
    3. 定义一个事件中心对象的 emit 方法，用于发布事件
    4. 定义一个事件中心对象的 off 方法，用于取消订阅事件
