### 2. JS 深浅拷贝
    1. 浅拷贝：只拷贝对象的引用，而不拷贝对象本身。
    2. 深拷贝：拷贝对象及其所有子对象。
    3. 浅拷贝实现方法
       1. Object.assign()
       2. 展开运算符 ...
    4. 深拷贝实现方法
       1. JSON.parse(JSON.stringify())
       2. 递归拷贝
       function deepClone(obj) {
        if (obj === null || typeof obj !== 'object') {
            return obj;
        }
        if (obj instanceof Date) {
            return new Date(obj);
        }
        if (obj instanceof RegExp) {
            return new RegExp(obj);
        }
        if (obj instanceof Array) {
            let clone = [];
            for (let i = 0; i < obj.length; i++) {
                clone[i] = deepClone(obj[i]);
            }
            return clone;
        }
        return obj;

        let clone = {};
        for (let key in obj) {
            if (obj.hasOwnProperty(key)) {
                clone[key] = deepClone(obj[key]);
            }
        }
        return clone;
       }

### 4. 浏览器缓存
    1. 内存缓存
    2. 磁盘缓存
    3. 服务端缓存
    4. 浏览器缓存策略
       1. 强缓存 ：通过设置 HTTP 响应头中的 Expires 和 Cache-Control 来实现，浏览器会根据这两个字段判断资源是否过期，如果过期则直接从缓存中读取，否则向服务器请求资源。
       2. 协商缓存：通过设置 HTTP 响应头中的 Last-Modified 和 ETag 来实现，浏览器会根据这两个字段判断资源是否更新，如果未更新则直接从缓存中读取，否则向服务器请求资源。
       3. 缓存失效：当资源过期或者未更新时，浏览器会向服务器请求资源，服务器会根据请求头中的 If-Modified-Since 和 If-None-Match 字段判断资源是否更新，如果未更新则返回 304 状态码，否则返回资源。

### 5. 微任务和宏任务
    微任务是指在当前任务执行完成后立即执行的任务，通常用于更新界面、处理异步操作等。
    宏任务是指需要等待当前执行栈中的所有同步代码都执行完成后才会执行的任务，通常用于定时器、网络请求等。
    1. 微任务：Promise、async/await、MutationObserver
    2. 宏任务：setTimeout、setInterval、I/O、UI 渲染
    3. 执行顺序：同步代码 > 微任务队列（如果有宏任务，则将宏任务放入宏任务队列）> 宏任务队列

### 6. vue2 和 vue3 的区别
    1. 响应式原理
        vue2: Object.defineProperty
            缺点：无法监听数组的变化，需要通过特殊的方式来监听数组的变化
        vue3: Proxy
            优点：可以监听数组的变化，不需要通过特殊的方式来监听数组的变化
    2. 虚拟 DOM
        vue2: 手动实现
        vue3: 基于 Proxy 实现
    3. 生命周期的区别
        vue2: beforeCreate、created、beforeMount、mounted、beforeUpdate、updated、beforeDestroy、destroyed
        vue3: onBeforeMount、onMounted、onBeforeUpdate、onUpdated、onBeforeUnmount、onUnmounted、onErrorCaptured
    4. 组件化的区别
        vue2: 基于选项式 API 实现
        vue3: 基于组合式 API 实现
    5. 性能的区别
        vue2: 性能相对较低
        vue3: 性能相对较高

### 9. vueX的五个属性
        1. state：存储应用状态的对象
        2. mutations：修改状态的方法，只能同步执行
        3. actions：处理异步操作的方法，不能直接修改状态，需要通过提交 mutations 来修改状态
        4. getters：计算状态的属性，类似于 computed 属性
        5. modules：将状态分割成多个模块，每个模块有自己的 state、mutations、actions、getters

### 17. ref和reactive的区别
        ref：
            1. 定义：ref 是 Vue 提供的响应式 API，用于定义响应式数据
            2. 类型：ref 可以定义任意类型的数据，包括对象、数组、函数等
            3. 访问：访问 ref 定义的数据时，需要使用 .value 属性
        reactive：
            1. 定义：reactive 是 Vue 提供的响应式 API，用于定义响应式对象
            2. 类型：reactive 只能定义对象类型的数据
            3. 访问：访问 reactive 定义的数据时，不需要使用 .value 属性
            4. 注意：reactive 定义的对象是深度响应式的，即对象内部的属性也会被监听
            5. 解决方法：可以使用 toRefs 函数将 reactive 定义的对象转换为 ref 定义的对象

### 18. 如果定义reactive的解构，怎么保证响应式
        1. 问题：如果定义 reactive 的解构，会导致解构后的数据不是响应式的
        2. 解决方法：可以使用 toRefs 函数将 reactive 定义的对象转换为 ref 定义的对象，然后解构
        3. 代码示例：
            1. const { name, age } = toRefs(state)
            2. 然后可以在模板中直接使用 name 和 age，而不需要使用 .value 属性
            3. 注意：toRefs 函数只能用于 reactive 定义的对象，不能用于 ref 定义的数据
            4. 解决方法：可以使用 toRef 函数将 ref 定义的数据转换为 ref 定义的对象，然后解构

### 20. setup和生命周期的区别
        setup：
            1. 组件初始化时调用
            2. 可以在 setup 函数中定义响应式数据、计算属性、方法等

### async await和promise的区别
    1. async await 是基于 promise 实现的，async 函数返回的是一个 promise 对象
    2. async await 可以使用 try catch 来捕获异常，而 promise 不能
    3. async await 可以使用 await 关键字来等待一个 promise 对象的状态变为 resolved，而 promise 不能
    4. async await 可以使用 return 关键字来返回一个值，而 promise 不能使用 return 关键字来返回一个值
    5. async await 可以使用 throw 关键字来抛出一个异常，而 promise 不能使用 throw 关键字来抛出一个异常
    6. async await 可以使用多个 await 关键字来等待多个 promise 对象的状态变为 resolved，而 promise 不能使用多个 await 关键字来等待多个 promise 对象的状态变为 resolved
    7. async await 可以使用 Promise.all 方法来等待多个 promise 对象的状态变为 resolved，而 promise 不能使用 Promise.all 方法来等待多个 promise 对象的状态变为 resolved


### BFC 和 IFC 的区别
    1. BFC：Block Formatting Context，块级格式化上下文
    2. IFC：Inline Formatting Context，行内格式化上下文
    3. 区别：BFC 是一个独立的渲染区域，而 IFC 是一个连续的渲染区域
    4. 应用场景：BFC 可以用于清除浮动，防止margin 合并等问题，而 IFC 可以用于文本环绕等问题
    5. 区别：BFC 可以包含浮动元素，而 IFC 不能包含浮动元素
    6. 区别：BFC 可以包含块级元素，而 IFC 只能包含行内元素
