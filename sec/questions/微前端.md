### 微前端
    微前端是指将一个大型前端应用拆分成多个小型前端应用，每个小型前端应用都可以独立开发、部署和运行。
    微前端的主要优势包括：
        1. 独立开发：每个小型前端应用都可以独立开发，开发人员可以使用自己熟悉的技术栈进行开发。
        2. 独立部署：每个小型前端应用都可以独立部署，部署人员可以根据需要选择合适的部署方式。
        3. 独立运行：每个小型前端应用都可以独立运行，用户可以在不影响其他应用的情况下使用自己喜欢的应用。
        4. 技术栈无关：每个小型前端应用都可以使用自己熟悉的技术栈进行开发，技术栈无关性使得开发人员可以根据需要选择合适的技术栈。
        5. 高度可维护性：每个小型前端应用都可以独立维护，维护人员可以根据需要选择合适的维护方式。

    微前端的主要挑战包括：
        1. 通信问题：微前端应用之间需要进行数据和状态的共享，这需要解决跨域、跨语言等问题。
        2. 路由问题：微前端应用之间需要进行路由的共享，这需要解决路由冲突、路由跳转等问题。
        3. 样式问题：微前端应用之间需要进行样式的共享，这需要解决样式冲突、样式隔离等问题。
        4. 性能问题：微前端应用之间需要进行性能的共享，这需要解决性能冲突、性能优化等问题。

    qiankun微前端隔离方案
        1. 沙箱隔离
            1.1 手动沙箱
                实现方式：通过在全局变量上添加前缀，或者在window对象上进行代理，实现对全局变量的隔离。
            1.2 代理沙箱
                实现方式：通过在window对象上进行代理，实现对全局变量的隔离。
                优势：可以实现对全局变量的完全隔离，避免全局变量的污染。
                劣势：实现起来比较复杂，需要对window对象进行代理。
        2. 样式隔离
            2.1 基于class的样式隔离
                实现方式：通过在每个微应用的样式中添加一个唯一的前缀，来实现样式的隔离。
            2.2 基于shadow DOM的样式隔离
                实现方式：通过在每个微应用的DOM中创建一个shadow root，来实现样式的隔离。
        3. 资源隔离
            3.1 静态资源隔离
                实现方式：通过在每个微应用的静态资源路径中添加一个唯一的前缀，来实现资源的隔离。
            3.2 动态资源隔离
                实现方式：通过在每个微应用的动态资源加载中添加一个唯一的前缀，来实现资源的隔离。

        4. 通信隔离
            4.1 基于事件的通信隔离
                实现方式：通过在每个微应用之间使用事件总线，来实现通信的隔离。
            4.2 基于消息队列的通信隔离
                实现方式：通过在每个微应用之间使用消息队列，来实现通信的隔离。
                优势：可以实现微应用之间的异步通信，避免同步通信的阻塞。
                劣势：实现起来比较复杂，需要对消息队列进行管理。
        5. 状态共享
            5.1 基于全局状态管理的状态共享
                实现方式：通过在每个微应用之间使用全局状态管理工具，来实现状态的共享。
            5.2 基于事件的状态共享
                实现方式：通过在每个微应用之间使用事件总线，来实现状态的共享。
                优势：可以实现微应用之间的状态共享，避免状态的重复加载。
                劣势：实现起来比较复杂，需要对事件总线进行管理。

    user: null,
    setUser(userInfo) {

        detail: userInfo
        }));

    });

    2. Event Bus
    // 创建一个事件总线
    // 事件总线 - 可以单独打包成公共库
    class EventBus {
    constructor() {
        this.events = {};
    }
    
    on(event, callback) {
        if (!this.events[event]) {
        this.events[event] = [];
        }
        this.events[event].push(callback);
    }
    
    emit(event, data) {
        if (this.events[event]) {
        this.events[event].forEach(callback => callback(data));
        }
    }
    
    off(event, callback) {
        if (this.events[event]) {
        this.events[event] = this.events[event].filter(cb => cb !== callback);
        }
    }
    }

    // 主应用初始化
    window.eventBus = new EventBus();

    // 子应用A - 发布事件
    function updateUser(user) {
    window.eventBus.emit('userUpdated', user);
    }

    // 子应用B - 订阅事件
    window.eventBus.on('userUpdated', (user) => {
    console.log('收到用户更新:', user);
    });

    3. 基于消息队列的状态共享
    // 消息队列 - 可以单独打包成公共库
    class MessageQueue {
    constructor() {
        this.queue = [];
    }
    
    enqueue(message) {
        this.queue.push(message);
    }
    
    dequeue() {
        return this.queue.shift();
    }
    }

    // 主应用初始化
    window.messageQueue = new MessageQueue();

    // 子应用A - 发送消息
    function sendMessage(message) {
    window.messageQueue.enqueue(message);
    }

    // 子应用B - 接收消息
    function receiveMessage() {
    const message = window.messageQueue.dequeue();
    if (message) {
        console.log('收到消息:', message);
    }
    }

### 样式隔离
    css-in-js
    自动生成唯一类名，避免冲突
    样式隔离：每个微应用的样式只对当前应用生效，不会影响其他应用。

        1. 基于class的样式隔离
        实现方式：通过在每个微应用的样式中添加一个唯一的前缀，来实现样式的隔离。
        优势：简单易用，不需要额外的配置。
        劣势：可能会导致类名冲突，需要手动避免。    

        2. 基于shadow DOM的样式隔离
            实现方式：通过在每个微应用的DOM中创建一个shadow root，来实现样式的隔离。
            优势：可以实现对样式的完全隔离，避免样式的污染。
            劣势：实现起来比较复杂，需要对DOM进行操作。
