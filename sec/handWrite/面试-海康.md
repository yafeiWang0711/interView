### 1. 智能表单工作流系统项目介绍、项目难点

**项目介绍**（示例框架，需结合实际）：

智能表单工作流系统用于企业流程自动化，支持**动态表单设计**（拖拽生成申请表单）、**流程引擎**（自定义审批节点、分支规则）、**数据联动**（不同部门表单字段关联）。核心模块：



*   表单设计器：可视化配置字段（输入框、下拉框、关联查询等），生成 JSON  schema。

*   工作流引擎：基于 BPMN 规范，配置审批人、会签 / 或签规则，支持条件分支（如 “金额> 10 万需财务总监审批”）。

*   数据中台：对接 ERP、OA 系统，实现表单数据跨系统同步。

**项目难点**：



*   动态表单渲染：需兼容复杂字段（如富文本、附件上传），且保证不同浏览器渲染一致性，用 `JSON Schema + Vue 动态组件` 实现。

*   流程状态管理：多分支流程的状态同步（如并行审批节点的进度合并），通过 `Redux/ Pinia` 维护全局流程状态，结合 WebSocket 实时推送审批变更。

*   性能优化：大表单（上百字段）的渲染卡顿，通过**虚拟滚动 + 按需渲染**（`Intersection Observer` 懒加载非视口字段）解决。

## 二、前端技术细节

### 4. Intersection Observer 除首页优化还能做些什么？

**核心能力**：监听元素与视口 / 容器的交叉状态，替代 `scroll` 监听，场景包括：



*   **懒加载扩展**：


    *   列表懒加载（如论坛无限滚动，滚动到底部自动加载下一页，替代 `scroll` 监听）。

    *   组件懒加载（如 “用户进入个人中心时，才加载复杂的账单组件”，减少首屏压力）。

*   **交互埋点**：统计广告 / 卡片真实曝光（可见比例 > 50% 才计数），用于业务数据分析（如 “首页轮播图点击转化率”）。

*   **动态资源加载**：进入视口才加载地图（`Google Maps API`）、视频（`<video autoplay>` 易卡顿，改为视口触发播放）。

*   **无障碍优化**：屏幕阅读器用户进入特定区域时，触发辅助提示（如 “此处有互动答题，按回车开始”）。

### 5. 虚拟滚动怎么用 Intersection Observer 做？

**核心逻辑**：仅渲染**视口内的列表项**，用 `Intersection Observer` 监听上下 “哨兵” 元素，触发数据加载 / 卸载。

**实现步骤**：



```
\<div class="virtual-list" style="height: 600px; overflow-y: scroll;">

&#x20; \<!-- 顶部哨兵：触发加载上一页 -->

&#x20; \<div class="sentinel top">\</div>&#x20;

&#x20; \<!-- 仅渲染可见区域的容器 -->

&#x20; \<div class="visible-items">\</div>&#x20;

&#x20; \<!-- 底部哨兵：触发加载下一页 -->

&#x20; \<div class="sentinel bottom">\</div>&#x20;

\</div>
```



```
// 监听哨兵，动态加载数据

const observer = new IntersectionObserver((entries) => {

&#x20; entries.forEach(entry => {

&#x20;   if (entry.isIntersecting) {

&#x20;     if (entry.target.classList.contains('top')) {

&#x20;       loadPrevPage(); // 加载上一页数据

&#x20;     } else {

&#x20;       loadNextPage(); // 加载下一页数据

&#x20;     }

&#x20;   }

&#x20; });

}, { root: document.querySelector('.virtual-list') });

// 观察哨兵

document.querySelectorAll('.sentinel').forEach(sentinel => {

&#x20; observer.observe(sentinel);

});
```

**优势**：



*   性能碾压 `scroll` 监听（无高频计算 `getBoundingClientRect`）。

*   精准控制渲染范围（如聊天记录滚动，只渲染最近 20 条 + 视口缓冲）。

### 6. 结合事件循环讲 Intersection Observer 的异步执行机制

**事件循环角色**：`Intersection Observer` 属于**宏任务**（浏览器任务），执行流程：



1.  **同步代码执行**：调用栈执行同步任务（如点击事件、初始渲染）。

2.  **微任务执行**：清空微任务队列（`Promise.then`、`async/await`）。

3.  **渲染更新**：浏览器执行渲染（如样式计算、布局绘制）。

4.  **宏任务执行**：`Intersection Observer` 回调进入宏任务队列，等待主线程空闲时执行。

**示例验证**：



```
console.log('同步任务开始'); // 1. 同步执行

// 微任务

Promise.resolve().then(() => {

&#x20; console.log('微任务执行'); // 3. 微任务

});

// 宏任务（Intersection Observer）

const observer = new IntersectionObserver(() => {

&#x20; console.log('Intersection 回调'); // 5. 宏任务

});

observer.observe(document.querySelector('#target'));

console.log('同步任务结束'); // 2. 同步执行

// 4. 渲染更新（若有 DOM 变化）
```

**输出顺序**：`同步任务开始` → `同步任务结束` → `微任务执行` →（渲染）→ `Intersection 回调`

### 7. Intersection Observer 执行时机与 Update、render 的先后关系（以 Vue 为例）

**Vue 渲染流程**：



1.  **Update 阶段**：数据变化触发组件更新（同步流程，如 `this.count++` 触发响应式更新）。

2.  **Render 阶段**：生成新的虚拟 DOM（同步流程，`render` 函数执行）。

3.  **Patch 阶段**：对比虚拟 DOM，更新真实 DOM（同步流程）。

4.  **宏任务执行**：`Intersection Observer` 回调属于**宏任务**，在上述同步流程后执行。

**结论**：

`Intersection Observer` 回调执行时，**DOM 已完成更新**（可安全操作最新 DOM 状态），但**不阻塞渲染**（浏览器有机会在回调前执行布局绘制）。

### 8. 微前端

**核心定义**：将巨型前端应用拆分为**独立开发、独立部署、运行时聚合**的子应用，解决**巨石应用维护难**（代码耦合、团队协作冲突）、**技术栈单一**问题。

**主流方案**：



| 方案                    | 核心原理                                                    | 适用场景                                  |
| --------------------- | ------------------------------------------------------- | ------------------------------------- |
| **Single-SPA**        | 主应用通过 `import-map` 加载子应用，监听路由变化                         | 多框架共存（Vue + React）                    |
| **qiankun**           | 基于 Single-SPA，支持 HTML Entry（子应用独立运行）、样式隔离（`shadow DOM`） | 旧系统渐进迁移（如 legacy jQuery 项目接入 Vue 新模块） |
| **Module Federation** | Webpack 5 特性，跨应用共享代码（如公共组件库）                            | 多团队共建组件库（避免重复打包）                      |

**落地难点**：



*   样式隔离：`qiankun` 用 `shadow DOM` + `CSS Modules`，但需处理第三方库样式污染（如 `AntD` 全局样式）。

*   全局状态共享：通过 `redux`/`pinia` 封装全局 store，主应用与子应用通过 `getGlobalState` 通信。

*   路由同步：主应用路由（如 `/home`）与子应用路由（如 `/home/profile`）深度整合，需配置 `history` 模式 + 路由前缀。

### 9. 讲讲 Web Worker 的详细信息

**核心作用**：在**独立线程**执行脚本，解决主线程阻塞（如大文件解析、加密计算）。

**基础用法**：



```
// 主线程

const worker = new Worker('worker.js');

worker.postMessage({ data: '加密内容' }); // 发送数据

worker.onmessage = (e) => {

&#x20; console.log('解密结果:', e.data); // 接收结果

};

// worker.js（独立线程）

self.onmessage = (e) => {

&#x20; const result = heavyCrypto(e.data); // 耗时操作

&#x20; self.postMessage(result);&#x20;

&#x20; self.close(); // 关闭线程

};
```

**核心特点**：



*   **线程通信**：通过 `postMessage` 传递数据，支持**结构化克隆**（深拷贝对象）或**Transferable Objects**（零拷贝传输 `ArrayBuffer`）。

*   **环境限制**：无 `window`/`document`（不能操作 DOM），但可访问 `fetch`、`WebSocket`、`localStorage`。

*   **类型**：


    *   `DedicatedWorker`：一对一通信（如 “用户上传文件时，单独线程解析”）。

    *   `SharedWorker`：多窗口共享线程（如 “多个 Tab 同步登录状态”）。

### 10. postMessage 和 onMessage 属于哪种设计模式？

**设计模式**：**发布 - 订阅模式（观察者模式）** 的异步变体。



| 角色      | 实现方式                      |
| ------- | ------------------------- |
| **发布者** | `postMessage`（发布 “消息” 事件） |
| **订阅者** | `onMessage`（订阅事件，执行回调）    |
| **解耦性** | 通信双方无需直接依赖，通过 “消息” 间接交互   |

**典型场景**：



*   跨窗口通信（如 `iframe` 与父窗口传递数据）。

*   Web Worker 线程通信（主线程与 Worker 线程传递加密任务）。

### 11. Web Worker 的线程池复用逻辑

**浏览器无内置线程池**，需手动模拟：



```
// 主线程：线程池管理

const workerPool = \[];

const MAX\_WORKERS = 4; // 最大线程数

// 初始化线程池

for (let i = 0; i < MAX\_WORKERS; i++) {

&#x20; const worker = new Worker('worker.js');

&#x20; worker.onmessage = handleResult;

&#x20; workerPool.push({ worker, isFree: true }); // 标记线程状态

}

// 提交任务

function submitTask(data) {

&#x20; const freeWorker = workerPool.find(worker => worker.isFree);

&#x20; if (freeWorker) {

&#x20;   freeWorker.isFree = false;

&#x20;   freeWorker.worker.postMessage(data);

&#x20; } else {

&#x20;   // 无空闲线程，任务排队

&#x20;   taskQueue.push(data);&#x20;

&#x20; }

}

// 处理结果，复用线程

function handleResult(e) {

&#x20; const worker = e.target;

&#x20; const poolItem = workerPool.find(item => item.worker === worker);

&#x20; poolItem.isFree = true;

&#x20; // 执行排队任务

&#x20; if (taskQueue.length > 0) {

&#x20;   const nextTask = taskQueue.shift();

&#x20;   worker.postMessage(nextTask);

&#x20;   poolItem.isFree = false;

&#x20; }

}
```

**适用场景**：高频任务（如批量数据加密），避免频繁创建 / 销毁线程的开销（线程初始化耗时～10-20ms）。

### 12. Web Worker 可以操作 DOM 元素嘛，能获取到 window 对象嘛？



*   **DOM 操作**：**不能**。Worker 线程无 `document`/`window` 对象（无 DOM 环境），若需操作 DOM，需通过 `postMessage` 通知主线程执行。

*   **window 对象**：Worker 线程中 `self` 等价于 `window`，但**不包含 DOM 相关属性**（如 `self.document` 为 `undefined`），可访问 `self.console`、`self.fetch` 等。

## 三、全栈 & Node.js

### 13. 了解 Node.js 嘛

**核心定位**：基于 V8 引擎的**服务端 JavaScript 运行时**，用事件驱动、非阻塞 I/O 实现高性能。

**典型场景**：



*   **服务端 API**：用 Express/NestJS 写后端接口（如用户登录、表单数据提交），对接数据库（MySQL、MongoDB）。

*   **工具链开发**：写 CLI 工具（如 “自动生成表单代码的脚本”）、Webpack  loader（自定义文件解析规则）。

*   **实时服务**：用 `Socket.IO` 实现 WebSocket 服务（如 “表单提交后，实时通知审批人”）。

**核心优势**：



*   **前后端同构**：前端组件（如 Vue）可服务端渲染（SSR），用 `Nuxt.js` 实现，提升 SEO 和首屏速度。

*   **生态丰富**：`npm` 包管理（如 `formidable` 处理文件上传、`jsonwebtoken` 生成登录态）。

### 14. Vue3 和 Vue2 的区别



| **维度**     | **Vue2**                              | **Vue3**                                     |
| ---------- | ------------------------------------- | -------------------------------------------- |
| **响应式原理**  | `Object.defineProperty`（递归劫持，初始化全量遍历） | `Proxy`（懒劫持，访问时才监听，性能更优）                     |
| **语法 API** | 选项式（`data`/`methods`）为主               | 组合式（`setup`/`ref`/`reactive`），更灵活，支持 TS 类型推导 |
| **包体积**    | 整体引入（`Vue.use`），Tree - Shaking 不彻底    | 按需引入（`import { ref } from 'vue'`），体积减少～41%   |
| **编译优化**   | 无静态提升                                 | 静态提升（`static hoisting`）、Patch Flag（精准更新 DOM） |

### 15. 讲讲 Vue3 的静态提升和 Patch Flag

#### 静态提升（Static Hoisting）



*   **作用**：编译时标记**静态节点**（如纯文本、无响应式绑定的元素），只渲染一次，更新时跳过。



```
\<template>

&#x20; \<!-- 静态节点：编译后会被提升，更新时复用 -->

&#x20; \<div class="static-title">固定标题\</div>&#x20;

&#x20; \<div>{{ dynamicText }}\</div>

\</template>
```

#### Patch Flag



*   **作用**：编译时为**动态节点**打标记（如 `1 /* TEXT */` 表示文本节点动态），更新时只处理带标记的节点，减少 DOM 操作。



```
\<template>

&#x20; \<div :class="dynamicClass">

&#x20;   {{ dynamicText }}&#x20;

&#x20; \</div>

\</template>

\<!-- 编译后简化示意 -->

createVNode('div', { class: \_dynamicClass }, \_dynamicText, 1 /\* TEXT + CLASS \*/)
```
